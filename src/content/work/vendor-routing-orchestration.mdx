I added an availability check to the routing path: on a failed call the router retries, and if the vendor is still unavailable it falls back to the next best vendor by weighted score. To stop wasting calls on a vendor that is down, I persisted failures in a table keyed by market, ZIP code and vendor. Once a vendor's failure count passes a configured threshold, it is excluded from the candidate set for that market and ZIP until a configured cooldown expires. After the cooldown, the next new order probes the vendor again: a success resets its status, and a failure starts another cooldown. In effect, it is a circuit breaker with closed, open and half-open states, scoped per market and ZIP code rather than per vendor globally, because a vendor can be healthy in one region and failing in another."

Orders had to reach the right vendor without a person deciding each time, and the background work around them had to survive failures without someone watching a console. Beyond routing, teams needed a way to define multi-step workflows and run them either when someone asks or on a timetable.

I built an orchestration module in Node.js for exactly that: workflows are configured, can be triggered on demand or scheduled, and run asynchronously with retries, automated recovery and metrics. I load tested the services, and API responses stayed under 2 seconds. Combined with a technician-facing app, the total 5G home internet installation came down to under 8 minutes.

This page describes the architecture generically, with no internal names, data or code.
